TinSu Design Directions

Design Direction Exploration

Exploring different visual approaches for TinSu based on the "Calm Command" theme

Core Emotion

"Leverage Without Anxiety"

Confident manager feeling — power with control

Defining Experience

"Drag to start, approve to ship"

Two actions, complete workflow

Primary Inspiration

Trello + Linear + Vercel

Instant Kanban + Developer polish + Real-time logs

Design Principles Applied

Keyboard-First

A Approve R Reject ←→ Navigate

Responsiveness Target

Card drag <16ms | Actions <100ms | Terminal real-time

Progressive Disclosure

Status at a glance, details on click

Docked Layout

Board + Terminal + Review in single view

Compare Directions

Trade-offs between different design approaches

Information Density

  • ● Compact (Dir 3) - See 3x more tasks
  • ● Classic (Dir 1) - Balanced visibility
  • ● Wide (Dir 2) - More detail per card

Terminal Visibility

  • ● Terminal Focus (Dir 4) - Maximum agent visibility
  • ● Classic (Dir 1) - Balanced dock
  • ● Minimal (Dir 6) - Ambient indicator only

Review Workflow

  • ● Split View (Dir 5) - Always-on review panel
  • ● Classic (Dir 1) - Slide-over on demand
  • ● Others - Modal or slide-over

Visual Weight

  • ● Minimal (Dir 6) - Lightest, content-forward
  • ● Classic (Dir 1) - Balanced structure
  • ● Wide (Dir 2) - More visual presence

Recommendation

Based on TinSu's goals of "Drag to start, approve to ship" and the 60-second velocity loop, I recommend:

1
Classic Kanban
  • ✓ Familiar Trello mental model — instant recognition
  • ✓ Balanced terminal visibility — watch without dominating
  • ✓ Slide-over review — maintains board context
  • ✓ Keyboard shortcuts prominent — power user friendly

Consider combining: Classic layout + Terminal Focus terminal size for users who want to "watch the teammate work."
